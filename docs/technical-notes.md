# 技术说明

这份文档给想了解原理、排查异常或维护项目的人。普通用户不需要阅读，也不需要根据它修改配置。

## 控制台做什么

控制台是一个只监听 `127.0.0.1` 的本地页面。它负责四件事：

1. 检查 Python、虚拟环境、ADB 和已连接手机。
2. 把页面输入转换成本地配置，并在写入前调用同一套配置校验。
3. 启动项目已有的演练或正式入口，不接受任意命令。
4. 轮询显示进程、手机和最近日志状态。

手机端的点击逻辑仍由 `mobile` 目录负责，控制台不改变热路径。

## 两种购票路径

### 预约连点型

预约阶段已经锁定场次和票档时，开售后不再读取票价文字，直接按已验证的坐标和顺序快速点击。由于手机页面可能用自绘控件隐藏状态，项目不依赖代码及时识别“预约”变成“购票”的文字变化。

它提供三个演练时机：

- `T0`：开售时立即发送首击，速度最快，可能撞上页面切换瞬间。
- `T0+10ms`：稍晚首击，通常更稳。
- `T0+20ms`：再晚一点，适合页面切换较慢的手机。

三个版本只应通过演练比较，不能根据电脑端日志猜测哪一档一定最好。

### 额外选择型

开售后仍有场次或票档卡片时，脚本使用用户确认过的可见卡片顺序，不按金额文字搜索。顺序从页面左到右、从 `1` 开始；页面换行时先数上一行，再数下一行。

这样少一次文字读取，速度更快，但每一场新演出都必须先演练。票价 `680`、`980`、`1280` 只是显示金额，不能直接填进顺序框。

## 正式任务状态

正式状态与演练状态分开计算：

- 没有有效正式时间：`未设置时间`。
- 已填写正式时间，但正式入口没有启动：`程序未就绪`，显示为红色。
- 正式入口已经启动并保持运行：`已准备就绪`，显示为绿色。
- 正式进程结束或异常退出：`正式任务未运行`。

正式任务应在开售前几分钟启动。看到绿色状态后，不要关闭控制台、锁屏或手动触碰手机。

## USB 与 ADB

本项目使用 ADB 发送调试命令，不使用手机的文件传输功能。Android 官方文档要求打开开发者选项中的 USB 调试，并用 `adb devices` 验证设备连接。

因此：

- 如果控制台显示 `ADB：已连接`，手机状态是 `device`，保持当前 USB 模式即可。
- “仅充电”通常不妨碍 ADB；“传输文件”主要是让 Windows 访问手机文件，不是本项目的必要开关。
- 如果 ADB 没有识别手机，再尝试切换到“传输文件”、重新插拔数据线、允许 USB 调试授权。切换文件传输属于排查手段，不是固定配置要求。

## 自动化边界

项目不自动搜索目标演出、不自动识别所有页面变化、不绕过验证码和排队，也不自动付款。页面布局、大麦版本、手机系统或字体设置发生变化后，应先演练确认路径，再考虑正式运行。
